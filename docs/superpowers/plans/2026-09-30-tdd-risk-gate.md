# TDD Risk Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `test-driven-development` before implementing any behavior-changing patch listed in this document. Do not write production code until a failing test has been written and observed. Do not implement anything from this plan unless the user explicitly approves a single patch.

**Goal:** กำหนดว่า logic จุดเสี่ยงใดของโปรเจกต์ต้องใช้ TDD/test-first ก่อนเขียนโค้ด และจุดใดไม่จำเป็นต้องใช้ TDD เต็มรูปแบบ

**Architecture:** แผนนี้เป็น gate ก่อน implementation โดยแยกงานเป็น `TDD Required`, `TDD Recommended`, และ `TDD Not Required` จากนั้นระบุ behavior ที่ต้องล็อกด้วย test ก่อนเขียน production code เพื่อไม่ให้ AI เดา logic จาก UI หรือแก้ปลายทางโดยไม่มีหลักฐาน

**Tech Stack:** Planning document only; target implementation context is TypeScript, Vitest or existing project test runner, Next.js/React components, OCR pipeline, PDF/export utilities

## Global Constraints

- ห้ามเขียน production code สำหรับ behavior-changing logic ก่อนมี failing test
- Test ต้อง fail ด้วยเหตุผลที่ถูกต้องก่อน implement
- Test ต้องล็อก behavior ไม่ใช่ล็อก implementation detail
- ห้ามใช้ UI screenshot เป็นหลักฐานว่า core logic ถูก
- ห้ามใช้ build ผ่านแทน unit/logic verification
- ถ้า test runner ยังไม่ทราบ ให้ตรวจ project scripts ก่อนใน patch นั้น
- ถ้า logic เกี่ยวกับเงิน, password, export, OCR, legal scoring หรือ dedup ต้องใช้ TDD

## TDD Classification

| งาน | ต้องใช้ TDD ไหม | เหตุผล |
|---|---:|---|
| เปลี่ยน label/button text เล็ก ๆ | ไม่จำเป็น | เป็น copy-only ถ้าไม่แตะ behavior |
| เปลี่ยนคำใน report preview | แนะนำ | ถ้าคำมี rule/condition ควรมี snapshot/text assertion |
| รวมยอดเงิน | ต้องใช้ | เงินผิดไม่ได้ |
| ตัดสลิปซ้ำจาก reference id | ต้องใช้ | ซ้ำแล้วนับเกิน/ตัดผิดกระทบยอดรวม |
| เรียงรายการตามวันเวลาโอน | ต้องใช้ | ลำดับในตารางเป็น requirement หลัก |
| mapping หน้า A4 | ต้องใช้ | ใช้อ้างอิงหลักฐานในรายงาน |
| OCR classification | ต้องใช้ | ถ้าจัดประเภทผิด downstream ผิดหมด |
| ตาราง export 12 คอลัมน์ | ต้องใช้ | เป็น output ลูกค้าและต้องไม่หลุดเลขบัญชี/ค่าธรรมเนียม/duplicate status |
| PDF real export | ต้องใช้ | preview ไม่เท่ากับ export จริง |
| PDF password encryption | ต้องใช้ + manual verify | ต้องพิสูจน์ว่าเปิดแล้วถามรหัสจริง |
| SFX packaging | ต้องใช้ + manual verify | ต้องพิสูจน์ว่าแตกไฟล์ได้และ branding ถูก |
| Legal triage scoring | ต้องใช้ | ห้ามฟันธงและต้องมี confidence/source quote |
| JEV readiness scoring | ต้องใช้ | เป็น decision layer ที่ต้อง explainable |

## Patch-Level TDD Gates

### Patch 1: Neutral Wording Only

**TDD Required:** No, unless wording is generated by conditional logic

**Test-First Scope If Needed:**

- [ ] report text must use neutral reference wording
- [ ] legal disclaimer must say preliminary/issue spotting
- [ ] no customer-facing label uses prohibited terms in key surfaces

**Acceptable Verification Without TDD:**

- Static text search
- Manual UI preview check

### Patch 2: Customer Transaction Data Model Only

**TDD Required:** Yes

**Behavior Tests To Write First:**

- [ ] maps raw transaction into customer-facing transaction summary
- [ ] preserves amount as number and formats later, not inside raw model
- [ ] keeps bank reference id
- [ ] excludes sender account from customer-facing row
- [ ] excludes receiver account from customer-facing row
- [ ] excludes fee from customer-facing row
- [ ] excludes duplicate status from customer-facing row
- [ ] carries source A4 page reference
- [ ] carries relationship status

**RED Expected Failure:**

- Model/builder does not exist, or fields do not match required customer-facing contract

**GREEN Requirement:**

- Minimal mapping utility passes only the declared behavior

### Patch 3: Table UI Only

**TDD Required:** Yes for table builder/columns; component tests recommended for rendering

**Behavior Tests To Write First:**

- [ ] renders exactly 12 columns
- [ ] column order matches final requirement
- [ ] amount displays 2 decimals
- [ ] does not render sender account
- [ ] does not render receiver account
- [ ] does not render fee
- [ ] does not render duplicate status
- [ ] sorts rows by transfer date/time
- [ ] shows evidence file as A4 page reference

**Example Test Intent:**

```text
Given transactions out of chronological order,
when customer ledger rows are built,
then rows are sorted by transfer date/time ascending
and customer-hidden fields are not present in row output.
```

### Patch 4: OCR / Slip-In-Chat Reliability Only

**TDD Required:** Yes

**Behavior Tests To Write First:**

- [ ] detects explicit slip candidate in chat image metadata/fixture
- [ ] classifies ambiguous candidate as review-required instead of confirmed
- [ ] preserves raw source reference
- [ ] does not drop high-value slip candidate because background is noisy
- [ ] emits confidence level
- [ ] emits reason for classification

**Fixture Requirement:**

- Use known missed files or minimal representative fixtures
- If real image fixture is too heavy, use extracted intermediate metadata fixture first

**Manual Verification Still Required:**

- Browser upload flow with known missed files

### Patch 5: Summary Cards Only

**TDD Required:** Yes

**Behavior Tests To Write First:**

- [ ] Card 1 total equals sum of deduped detected transactions
- [ ] Card 2 total is 0 when no POI checkbox is selected
- [ ] Card 2 total includes selected POIs only
- [ ] Card 3 uses relationship/page mapping summary, not linkage detail table
- [ ] Card 4 does not expose duplicate-status wording in customer-facing display
- [ ] inactive card is omitted from executive summary payload

**Integration Check:**

- Toggle card state and assert report payload/output changes accordingly

### Patch 6: PDF Real Export Only

**TDD Required:** Yes for export function contract

**Behavior Tests To Write First:**

- [ ] export function creates a real file/blob payload
- [ ] export includes report content from stable report data
- [ ] preview path and export path are distinct
- [ ] export status does not claim encryption when password is not applied

**Manual Verification Still Required:**

- Open exported PDF file manually

### Patch 7: PDF Password Encryption Only

**TDD Required:** Yes, plus real viewer/manual validation

**Behavior Tests To Write First:**

- [ ] password field is passed only to PDF encryption path
- [ ] export metadata records password-protected intent
- [ ] empty password produces unencrypted export or blocks according to approved rule
- [ ] PDF password state is separate from SFX password state

**Manual Verification Required:**

- Open exported PDF in a PDF viewer
- Confirm password dialog appears
- Correct password opens
- Incorrect password fails

### Patch 8: SFX Real Packaging Only

**TDD Required:** Yes for package manifest/config generation

**Behavior Tests To Write First:**

- [ ] package manifest includes expected files
- [ ] SFX config contains product name
- [ ] SFX config contains disclaimer text
- [ ] SFX config uses SFX password only when enabled
- [ ] SFX password is separate from PDF password
- [ ] package excludes temporary/internal files

**Manual Verification Required:**

- Open SFX
- Confirm branding screen
- Extract package
- Confirm extracted files

### Patch 9: Legal Triage Scoring Only

**TDD Required:** Yes

**Behavior Tests To Write First:**

- [ ] rule output uses `preliminary` or Thai equivalent wording
- [ ] every detected issue contains source quote/reference
- [ ] every detected issue contains confidence
- [ ] keyword-only match without transaction support does not become high confidence
- [ ] civil and criminal categories remain separate
- [ ] no output uses final-judgment wording

**Manual/Expert Verification Recommended:**

- Human legal review of rule definitions before customer-facing use

### Patch 10: JEV Readiness Scoring Only

**TDD Required:** Yes

**Behavior Tests To Write First:**

- [ ] readiness score increases when required evidence links are present
- [ ] readiness score decreases when OCR confidence is low
- [ ] readiness output includes reason list
- [ ] readiness does not override raw evidence data
- [ ] readiness does not convert uncertain data into confirmed data

**Precondition:**

- JEV license/source concept reviewed before implementation

## Test-First Checklist For Any Risky Patch

Before writing production code:

- [ ] Identify behavior in one sentence
- [ ] Write one failing test for that behavior
- [ ] Run the test and confirm it fails for the expected reason
- [ ] Implement minimal code only for that behavior
- [ ] Run the test and confirm it passes
- [ ] Run adjacent tests affected by the same data contract
- [ ] Refactor only after green
- [ ] Report which tests were RED first and then GREEN

## Anti-Patterns To Block

- [ ] Writing UI first and backfilling logic later
- [ ] Writing tests after implementation
- [ ] Test passes immediately on first run
- [ ] Test checks mock behavior instead of real utility behavior
- [ ] Test checks CSS class only while business logic is untested
- [ ] Using one giant E2E test instead of small logic tests for money/dedup/sort
- [ ] Claiming OCR fixed from one screenshot
- [ ] Claiming PDF password works without opening exported PDF
- [ ] Claiming legal triage is accurate without source quote/confidence

```text
- เรียงตามวันเวลา
- ไม่แสดงเลขบัญชีผู้โอน
- ไม่แสดงเลขบัญชีผู้รับ

รันให้เห็นว่า fail ก่อน แล้วค่อย implement minimal code
ห้ามแตะ PDF export, password, SFX, OCR, legal triage
```

## Self-Review

- Spec coverage: ครอบคลุม logic จุดเสี่ยงที่ผู้ใช้ระบุ เช่น รวมยอด, dedup, sort, A4 mapping, PDF password, OCR classification, table export, legal scoring
- Scope control: ระบุว่างาน label เล็ก ๆ ไม่จำเป็นต้องใช้ TDD เต็มรูปแบบ
- Conflict alignment: สอดคล้องกับ Patch Slicing Execution Checklist และ Implementation Sequence
- Placeholder scan: ไม่มี placeholder ที่ต้องเดาเอง
- Unknown: ยังไม่ได้ตรวจ test runner จริงของโปรเจกต์
- Untested: ยังไม่ได้เขียน test, run test, build, browser, PDF, หรือ SFX จริง
